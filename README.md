1) 病人端（DocumentReference_user.html）

  用途： 病人自己上傳檢驗報告（PDF）後，把「雲端連結」存到 FHIR，並只能查看自己的文件。
  
  你可以做的事：
  
    建立文件索引（新增）
    先把 PDF 上傳到雲端（Drive/S3…），再把 雲端連結 URL 填進來，系統會建立一筆 DocumentReference。
    
    查詢我的文件清單（查詢）
    只會看到 自己（固定病人 ID） 的文件，並顯示科別/類型/標題。
    
    開啟文件（檢視）
    點「開啟 PDF 連結」會用雲端 URL 直接開檔，FHIR 不存檔案本體。

2) 醫護端（DocumentReference_doctor.html）

  用途： 檢驗科醫護替病人建檔、查詢檢驗科文件，並只修改「臨床內容」。
  
  你可以做的事：
  
    替病人建立文件索引（新增）
    填病人 ID、PDF 雲端連結、標題等欄位，建立檢驗報告的 DocumentReference。
    
    依病人查詢文件（查詢）
    依病人查詢後，系統只顯示「檢驗科」相關的文件（模擬只看自己科別的病人資料）。
    
    修改臨床內容（修改）
    只允許修改 備註（description） 和 文件狀態（docStatus），避免亂改連結、病人歸屬、分類等索引資訊。

3) 管理者端（DocumentReference_admin.html）

  用途： 管理者處理「索引資料」：建立、查詢、修正 metadata、下架/作廢。
  
  你可以做的事：
  
    建立文件索引（新增）
    管理者也可建立 DocumentReference（通常用於測試或例外處理）。
    
    依病人查詢文件（查詢）
    查到該病人的所有文件索引清單，方便確認資料是否正確。
    
    修正索引/下架（修改/下架）
    可修正：標題、分類、連結、contentType、病人關聯（少用）等；
    若文件不該被看到，可將 status 設為 entered-in-error 來「作廢/下架」。
